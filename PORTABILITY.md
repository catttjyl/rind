# RIND v2.3.0 portable source and CPU smoke

Base source: Git commit `d6653415ec5c7845b3a412dba58d4044bb6bc01f`; exported without `.git`. The upstream project metadata intentionally still says `2.2.0rc5`; commit identity is authoritative here. Added only this note, pinned environment list, `scripts/eval_repr_sufficiency.py`, and `vendor/ray_query/`.

Python 3.12.14, PyTorch 2.8.0, NumPy 2.3.3 and transitive versions used on macOS are pinned in `requirements-cpu-macos-py312.txt`. This is a version lock, not a cross-platform wheel/hash lock. Python and wheel distributions are not bundled; an offline machine must have compatible wheels supplied in advance. Install, for example, with `python3.12 -m venv .venv` and `.venv/bin/pip install -r requirements-cpu-macos-py312.txt`; for a truly disconnected machine add `--no-index --find-links <wheelhouse>` after preparing the wheelhouse. Linux/CUDA builds and compatibility remain untested.

`vendor/ray_query/ray_query.c` and its optional adapter `native_ray_query.py` are copied from the separate local `AI-Talent-Mapping/交付结果/RIND全年全点训练-20261113/` annual-run package, not from the d665341 Git tree. The core RIND path and the 24-bin smoke do not install or require the native adapter. The adapter monkey-patches `RayCandidateScene.query` only when explicitly installed; build a matching shared library for the target OS and separately verify parity before use. It is not the `ExactSceneBVH` used for synthetic truth. No compiled binary is shipped.

Run from this directory: `python scripts/eval_repr_sufficiency.py --device cpu --checkpoint /path/to/calibrated.pt --output /path/to/result.json --seed 20261114`. Omitting the checkpoint creates a seeded, untrained model for interface checks only. The built-in scene and evaluation are synthetic; checkpoint loading here does not establish split provenance for real-data evaluation.

## Read-only indexed shards (stage 2)

`train`, `calibrate`, and `eval`/`eval-fullday` accept both `--portable-index PATH` and `--portable-index-sha256 SHA256`. Supply the exact index SHA from a separately trusted freeze record; a hash placed only next to the data does not establish authenticity. Package the unchanged split and annual manifest as well. Point `--cache-dir` to the read-only shard tree. The reader binds the active split, manifest, tile role, source and mesh provenance, time/receiver/candidate configuration, array hashes, shapes and dtypes; any missing or invalid shard aborts without a cache rebuild or raw-source fallback. Keep the index and all shards immutable while in use. Verification reads every array and can be costly on annual data.

`scripts/make_portable_index.py --help` describes verification and index creation. Its default formal path requires the exact 67 fit / 12 calibration / 14 validation tile set; the partial-index switch is limited to synthetic fixtures. Use separately isolated cache directories for different candidate configurations. A four-season package remains diagnostic only. In portable evaluation, blocker-distance and contour diagnostics require the original scene-reader path and are rejected; pass `--no-blocker-distance-buckets --no-shadow-contours` where the checkpoint enables them. Other commands, including inverse design and raw-vs-cache latency benchmarks, are not supported by portable mode. This patch changes the stage-1 code snapshot; freeze a new code hash before any future experiment.
